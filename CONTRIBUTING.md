# Contributing Guidelines

Thank you for your interest in contributing to this project! This document outlines the contribution process and guidelines.

## How to Contribute

1. **Fork the Repository**: Create your own fork of this repository.
2. **Create a Branch**: Create a feature branch for your changes.
3. **Make Changes**: Implement your changes following the coding standards.
4. **Test**: Ensure all tests pass before submitting.
5. **Submit a Pull Request**: Open a PR with a clear description of your changes.

## Code of Conduct

- Be respectful and inclusive.
- Provide constructive feedback.
- Follow the project's coding standards.

## Pull Request Process

1. Ensure all status checks pass.
2. Request a review from a maintainer.
3. Address any feedback promptly.
4. PRs require at least one approval before merging.

## Payment Terms

### GitHub Sponsors
This project supports GitHub Sponsors for financial contributions. Sponsors help maintain and improve the project.

### Paid Contributions
For paid contributions or commissioned work:
- Payment terms are agreed upon before work begins.
- Trusted payment gateways (GitHub Sponsors, PayPal, etc.) are used.
- Automated invoicing is linked to repository releases when applicable.

### Licensing
- Contributions are licensed under the same license as the project (MIT).
- Dependencies must be checked for license compatibility before inclusion.

## Reporting Issues

- Use GitHub Issues for bug reports and feature requests.
- Use GitHub Discussions for questions and general support.
- Escalation paths are documented to avoid missed complaints.
