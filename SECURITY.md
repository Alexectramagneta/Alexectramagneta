# Security Policy

This repository follows strict security rules to ensure legal safety, reliable operations, and data protection.

## 🔐 Security Rules

### Branch Protection
- Require pull request reviews before merging.
- Enforce status checks (tests, security scans) before merges.
- Prevent force pushes and branch deletions.

### Access Control
- All collaborators must enable two-factor authentication (2FA).
- Roles are assigned with least privilege (Owner, Security Manager, Reviewer).
- Admin rights are limited to trusted maintainers.

### Secret Management
- No API keys, payment credentials, or customer data stored in code.
- GitHub Secret Scanning enabled.
- Dependabot alerts monitored and resolved promptly.

### Audit & Logging
- Audit logs enabled for all repositories.
- Logs reviewed monthly for unauthorized activity.

## Reporting a Vulnerability

If you discover a security vulnerability, please report it responsibly:

1. **Do not** open a public issue.
2. Email the maintainer at: fearlessupstairs47@gmail.com
3. Include a detailed description of the vulnerability.
4. Allow reasonable time for a response before public disclosure.

We will acknowledge your report within 48 hours and aim to resolve critical vulnerabilities promptly.
